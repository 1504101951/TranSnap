## 维护规则

1. **GitHub Issue 为唯一规格源**：已确认需求先更新对应规格或功能 Issue，再进入开发；已完成且说明完备的规格不再保留重复的本地正文副本。
2. **本地例外条件**：仅当未关闭 Issue 中的已确认细节不适合直接承载在 Issue 内时，才保留单独本地规格，并在文档注明关联 Issue、会话标记（`<框架名>-Thread`）与保留范围。
3. **辅助文档职责分离**：`docs/index.md`、`docs/architecture.md`、`docs/glossary.md` 与 `docs/agents/` 仅负责导航、当前实现说明、术语统一与协作规范，不替代规格裁决。
4. **状态与标签纪律**：未定数值和未拍板交互标为「待澄清」，不按可开发处理；智能体只更新正文、评论与中文标签，不关闭 Issue。
5. **验收分工**：智能体负责静态分析、自动化测试、构建与签名核验；界面效果由用户亲自验收，禁止使用 computer-use。
